# Phase: Brainstorm

Find the current session directory (most recent under `docs/dev-sessions/`). Read `spec.md` for initial context — it may be empty or contain an initial description.

Ask questions one at a time to develop a thorough, detailed spec. Each question should build on previous answers. The goal is a specification detailed enough to hand off to a developer. Only one question at a time — do not ask multiple questions in a single message.

Good questions to work through:
- What problem is being solved, and for whom?
- What are the concrete inputs and outputs or user interactions?
- What are the acceptance criteria — how do we know it's done?
- What are the constraints (tech stack, existing patterns, performance, etc.)?
- What edge cases or failure modes need handling?
- What explicitly is out of scope for this session?

When the brainstorm feels complete, confirm with the user, then save the results to `spec.md` — preserve any existing content and incorporate all brainstorm refinements into a cohesive document.
